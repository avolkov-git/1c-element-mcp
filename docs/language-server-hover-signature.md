# Hover и Signature Help

Версия MCP `0.18.0` добавляет две read-only операции штатного Language Server Element 9.2.4:

- `get_hover` — тип, краткое объявление и документация для позиции;
- `get_signature_help` — доступные перегрузки и активный параметр вызова.

Обе команды работают только внутри подключённого проекта. Путь задаётся относительно его корня, строки и
колонки начинаются с единицы. На уровне протокола MCP преобразует колонку в UTF-16, как требует LSP 3.17, поэтому
позиции после кириллицы и символов вне BMP не смещаются.

## Контракт Hover

Точный ответ содержит:

- `lsp_status`: `ready` или `empty`;
- `found`: есть ли непустое содержимое;
- `contents`: не более 16 блоков `markdown`, `plaintext` или `code`;
- `range`: необязательный диапазон символа с координатами от единицы;
- `truncated`: был ли ответ ограничен.

MCP поддерживает актуальный `MarkupContent` и прежние варианты `MarkedString`: строку, код с языком и массив этих
значений. Пустой Markdown считается отсутствием информации в позиции, а не ошибкой сервера.

## Контракт Signature Help

Точный ответ содержит не более 20 сигнатур и 50 параметров в каждой:

- `active_signature` и `active_parameter` — проверенные индексы либо `null`;
- `label` и документацию каждой перегрузки;
- параметры со строковым `label` либо парой `label_offsets`;
- необязательный `active_parameter` конкретной перегрузки;
- общий признак `truncated`.

Суммарный текст ответа ограничен 24 000 символов, отдельный блок — 8 000. Индексы за пределами уже
нормализованного массива не возвращаются.

## Состояния и fallback

`lsp_status` не смешивает разные ситуации:

| Значение | Смысл |
|---|---|
| `ready` | LSP вернул непустой точный результат |
| `empty` | LSP ответил успешно, но в позиции нет информации |
| `unsupported` | Запущенный сервер не объявил capability |
| `timeout` | Запрос превысил лимит ожидания и был отменён |
| `stopped` | Runtime не настроен, завершился или потеряна связь |
| `error` | LSP обработал запрос с ошибкой |

При `unsupported`, `timeout`, `stopped` или `error` MCP пытается найти локальное объявление. Hover показывает
строку объявления. Signature Help показывает возможные строки методов, но не вычисляет типы, перегрузку и
активный параметр. Такой результат всегда имеет `analysis_mode: syntax-aware lexical fallback`,
`semantic_guarantee: false` и `fallback_reason`.

## Runtime 9.2.4

JAR `com.e1c.g5rt.lsp.server.appengine-9.2.4-1.jar` объявляет `hoverProvider` и
`signatureHelpProvider` с trigger characters `(` и `,`. MCP заявляет совместимые client capabilities при
`initialize` и запускает процесс с module access, необходимым встроенному Apache Ignite.

JAR собран JDK 11. На Java 21 воспроизводимый локальный smoke-test показал, что сам LSP и синтаксическая часть
запускаются, но старая версия Ignite не может полностью поднять типовую модель (`jdk.internal.misc.SharedSecrets`),
из-за чего Hover бывает пустым, а Signature Help отвечает внутренней ошибкой. MCP корректно переходит к fallback,
но для проверки точной семантики этой поставки следует использовать Java 11 или штатную Java целевой установки.

## Рекомендуемый порядок

1. Вызвать `get_language_server_status(start=true)` и проверить обе capability.
2. Передать точный относительный путь и позицию редактора в `get_hover` или `get_signature_help`.
3. При `empty` не повторять запрос без изменения позиции или файла.
4. При fallback явно сообщить пользователю, что результат не подтверждён компилятором.
5. После изменения кода отдельно вызвать `get_project_diagnostics`.
