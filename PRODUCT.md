# Product

## Register

product

## Platform

web

## Users

The primary user is the owner or administrator of a 1C:Enterprise.Element server. They open the page locally on the same Windows Server where Codex and MCP run, usually to confirm that MCP is alive and keep it current. The same product must remain usable in a closed network with no internet access.

## Product Purpose

1C Element MCP gives AI agents local, version-aware access to Element documentation and, over time, project tooling. Its web surface exists to answer whether MCP is running, whether a safe update is available, and which trusted Git source supplies that update.

## Positioning

The smallest trustworthy control surface for a local 1C Element AI bridge.

## Brand Personality

Calm, precise, and unobtrusive. The interface should feel like a dependable system utility, not a developer demo or a full management console.

## Anti-references

Avoid data-dense dashboards, terminal cosplay, oversized metrics, decorative gradients, glass effects, card grids, and navigation that has no job on the current screen. Lack of network access is an expected operating condition, not an alarming failure.

## Design Principles

- Status comes first and is stated in plain language.
- One screen has one primary action.
- Progressive disclosure keeps configuration out of the common path.
- A user-selected local source turns checking and applying an update into one deliberate action.
- Offline and closed-network states stay honest and actionable.
- Familiar controls and immediate feedback build trust.

## Accessibility & Inclusion

The web UI supports keyboard operation, visible focus, semantic status announcements, sufficient contrast, text scaling, system dark mode, and reduced motion. Color never carries status by itself.
