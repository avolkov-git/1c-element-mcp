# История изменений

Проект следует [Semantic Versioning](https://semver.org/).

## [0.20.0] - 2026-08-18

- Добавлены prepare/execute tools для загрузки сборки, обновления, запуска и остановки приложения через точные
  маршруты Console API Element `9.2.4-6`, а также bounded `wait_console_task`.
- Управляемые действия выключены после установки. Локальный UI задаёт allowlist операций, UUID проектов и
  приложений и каталоги сборок; агент не может менять эту политику через MCP tools.
- Prepare возвращает точную цель, параметры, риски и одноразовый токен на пять минут. Токен связан с
  precondition и отпечатком политики, хранится в памяти как SHA-256 и расходуется до внешнего запроса.
- Загрузка проверяет обычный ZIP внутри разрешённого каталога, размер, корневой Project YAML, configuration ID и
  SHA-256 до и во время execute. Update/start/stop повторно сверяют состояние Console перед записью.
- POST и PUT выполняются один раз без автоматического retry. Неоднозначный результат возвращает read-only план
  сверки и запрещает повторное использование токена.
- Добавлен защищённый audit log с отдельной записью до сетевого изменения и redaction credentials. Approval
  token, тело сборки и Console credentials в log не записываются.
- Unit, UI и MCP protocol tests покрывают default deny, allowlist, expiry, replay, tampering, precondition,
  ambiguous failure, exact request body, task polling и отсутствие секретов.

## [0.19.0] - 2026-08-18

- Добавлены девять read-only tools для runtime health, процесса, диска, server logs, Application Event Log и
  точной корреляции операций.
- Instance root проверяется по штатным `config/server.yml`/`config/logging.yml`; файловые операции принимают
  только allowlisted `log_id`, не следуют по symlink и ограничивают файлы, байты, строки и совпадения.
- Подтверждены внутренние маршруты Application Manager Element 9.2.4-6: V1 GET, V2 POST, anchor, обязательный
  диапазон, фильтры и отдельный V1 GET события. Auto-режим безопасно деградирует с V2 на V1.
- В локальный UI добавлена необязательная настройка instance root и внутреннего Application Manager. Его Basic
  credentials отделены от Console Client ID/Secret, защищаются DPAPI/ACL на Windows и не возвращаются агенту.
- Добавлена единая redaction policy для credentials, email, user ID, свойств событий и ограниченных stack traces.
- `trace_operation` соединяет только точные task/application/trace/request/operation ID, показывает происхождение
  каждой части и честно возвращает gaps при недоступном источнике.
- Тесты покрывают ротацию, binary/invalid UTF-8, path traversal, symlink, временные зоны, лимит диапазона,
  V2→V1 fallback, 401, anchor и отсутствие секретов в MCP/UI-ответах.

## [0.18.0] - 2026-08-18

- Добавлены read-only `get_hover` и `get_signature_help` поверх штатного Language Server Element.
- Hover нормализует Markdown, plaintext и legacy MarkedString в ограниченные структурированные блоки; пустая
  позиция не выдаётся за сбой.
- Signature Help сохраняет перегрузки, активную сигнатуру и параметр, документацию, строковые и offset-метки;
  число сигнатур, параметров и объём текста ограничены.
- Позиции MCP остаются 1-based и преобразуются в 0-based UTF-16 LSP; закрытый документ открывается лениво.
- `lsp_status` отдельно сообщает `ready`, `empty`, `unsupported`, `timeout`, `stopped` и `error`. Лексический
  fallback показывает только найденные объявления и всегда снимает compiler-level гарантию.
- Инициализация клиента теперь объявляет hover/signature capabilities, а статус показывает фактическую поддержку
  сервера. В команду запуска добавлены JVM exports/opens, требуемые семантическим ядром Element 9.2.4.
- Fake LSP и MCP protocol tests покрывают MarkupContent, MarkedString, перегрузки, пустые ответы, лимиты,
  конвертацию позиции и деградацию runtime.

## [0.17.0] - 2026-08-18

- Добавлен инкрементальный граф YAML-элементов, companion XBSL/XBQL, подсистем, environment, visibility и
  объявлений XBSL.
- Явные imports/Using, YAML UUID/type/handler и lexical references представлены разными рёбрами с evidence,
  confidence и resolution; граф не выдаётся за результат компилятора.
- Добавлены `get_element_dependencies`, `get_project_dependency_graph` и объяснимый обратный
  `analyze_change_impact` с лимитами глубины, узлов и рёбер.
- Добавлен `get_changed_elements`: локальный VS Code использует read-only Git status, а Element IDE честно
  запрашивает diff paths, которых нет в штатном `g5rt.team.status`, и не запускает второй Git.
- Добавлены структурная проверка imports, handlers, UUID, неоднозначных имён, orphan-файлов и циклов, а также
  осторожный low-confidence поиск кандидатов на неиспользуемые элементы.
- Произвольные YAML/XBSL внутри специальных каталогов `Resources`/`Ресурсы` больше не принимаются за живые
  элементы; лексический анализ корректно продолжает работу после строк с вложенной интерполяцией.
- Кэш повторно разбирает только изменённые файлы; path/symlink boundaries, удаление/rename, большие циклы и
  bounded responses покрыты unit и настоящими MCP protocol tests.

## [0.16.0] - 2026-08-18

- Добавлен `get_console_server_info`: health, доступность API v2, capability map и честное разделение версии
  проверенного контракта `9.2.4-6` от неизвестной версии удалённого сервера.
- Добавлены список приложений пространства, явная/IDE-карточка приложения и отдельные status, technology,
  project и endpoints.
- Добавлено read-only чтение списка и карточки сборок проекта, application/deployment/group tasks.
- Текущий application ID используется только из активного plugin handoff; в обычном VS Code требуется явный UUID.
- Добавлены ограниченные локальные фильтры и пагинация, timeout и повторы только безопасных GET после временных
  сетевых ошибок, `429`, `502`, `503` и `504`.
- DTO проходят allowlist и redaction; сертификаты, domain-validation payload, user lists и credentials исключены,
  а внешние ответы помечаются как недоверенные данные.
- Добавлены mock API и MCP protocol tests для exact routes, трёх типов задач, выбора окружения, пустых/ошибочных
  ответов, версионной совместимости и отсутствия секретов.

## [0.15.0] - 2026-08-18

- Добавлен проверяемый `reference-catalog.json` и безопасный read-only слой структурированных JSON/JSONL-наборов.
- Добавлены `list_reference_datasets`, ограниченный `query_reference` и typed tools для операций/схем Console API,
  компонентов, точек входа и связей server bundle.
- Операция Console API возвращается вместе с разрешёнными схемами, версией, dataset ID и происхождением.
- Нормализатор `1.1.0` воспроизводит 166 операций и 87 схем Console API из встроенных Docusaurus-данных, графы
  ссылок и структурированные описания фактически найденной поставки Windows/Linux.
- Конфигурационный справочник сохраняет только имена ключей и хеши, не значения с возможными секретами.
- Валидация проверяет границы путей, схему каталога, число JSONL-записей и SHA-256; старые корпуса без справочника
  остаются пригодными для полнотекстового поиска.

## [0.14.0] - 2026-08-14

- В локальном UI появился статус нормализованной документации с точным путём активного корпуса.
- Путь можно изменить через раскрываемую настройку: MCP полностью проверяет манифест, три корпуса, JSONL, SQLite и векторные индексы, а затем вызывает тот же контракт, что и `activate_documentation`.
- Ошибочный каталог не заменяет прежний активный корпус; UI сохраняет введённый путь, показывает причину рядом с полем и позволяет исправить её.
- Путь, заданный через `--corpus-path` или `ELEMENT_DOCS_PATH`, честно отображается как управляемый запуском и не может быть незаметно переопределён из UI.
- Добавлены loopback/CSRF-защищённые HTTP-маршруты состояния и активации документации, состояния загрузки и адаптивное отображение длинных путей.

## [0.13.0] - 2026-07-21

- Добавлен read-only инструмент `get_current_application`, который получает точную карточку опубликованного приложения из `1C.applicationId` активной Element IDE-сессии.
- Ответ содержит безопасные сведения о статусе, URL, режиме разработки и отладки, версии технологии, проекте и опубликованной сборке, текущей задаче и ошибке приложения.
- Инструмент намеренно не принимает `application_id` и недоступен для обычного VS Code или постоянной Console-конфигурации: текущим считается только приложение, переданное штатным IDE handoff.
- Codex Element plugin передаёт `1C.applicationId` вместе с существующим временным контекстом, не раскрывая Client Secret или bearer token модели.
- MCP сопоставляет проект карточки приложения со штатным `1C.projectId` и явно сообщает результат проверки связи.

## [0.12.0] - 2026-07-21

- Добавлен безопасный IDE workspace handoff: Element-плагин передаёт локальные `workspaceFolders`, текущий `project_id` и сводку штатной команды `g5rt.team.status` без Git credentials и commit message.
- MCP различает Console-проект, Git workspace и корень проекта Element; единственный `Project.yaml` подключается в памяти автоматически, а несколько кандидатов требуют выбора пользователя.
- Добавлен read-only инструмент `match_console_project` для сопоставления проекта Console с локальными кандидатами в Element IDE и VS Code. Совпадение имени всегда помечается как требующее подтверждения.
- IDE-контекст не записывает временный путь workspace в постоянный `config.json`; ручной выбор среди кандидатов живёт до смены или завершения IDE-сессии.
- Обнаружение ограничено 16 workspace folders, 10 000 каталогов и 100 проектами, не следует по symlink и не читает исходники вне найденных манифестов.

## [0.11.0] - 2026-07-21

- В локальный UI добавлено необязательное подключение к удалённому серверу Element для VS Code и других внешних клиентов: URL, Client ID и Client Secret.
- Подключение проверяется получением токена и чтением пространств до сохранения; его можно выключить и включить снова без удаления защищённого секрета.
- UI никогда не возвращает сохранённый Client Secret. На Windows он защищается DPAPI LocalMachine и ACL, на POSIX отдельный `console.json` получает права `0600`.
- Точный token flow подтверждён официальной документацией и исходниками Console 9.2.4: HTTP Basic, `POST /console/sys/token`, `grant_type=CLIENT_CREDENTIALS`, bearer из `id_token`, повторное получение после `401`.
- Добавлены CSRF/Host-защита нового endpoint, лимиты тела, атомарная запись и тесты отсутствия секрета в ответах и неуспешных конфигурациях.

## [0.10.0] - 2026-07-21

- Добавлен адаптер к штатному Language Server Element из серверного бандла: отдельный STDIO-процесс на активный проект, JSON-RPC lifecycle и ограниченный клиент обратных запросов.
- `get_definition` и `get_references` выполняют compiler-level навигацию по позиции файла и автоматически переходят к лексическому индексу с явной потерей семантической гарантии, если LSP недоступен.
- `get_project_diagnostics` возвращает только опубликованные LSP-диагностики, состояние builder/indexer и признак полноты; лексический индекс не выдаётся за компилятор.
- `get_language_server_status` проверяет проект, полный бандл, совместимость patch-версий LSP и Element и Java 11+; `configure_language_server` сохраняет только проверенный пользователем runtime.
- Воспроизведена точная команда запуска IDE 9.2.4 по source map плагина и байткоду `AppEngineServerMain`; реальный JAR 9.2.4-1 прошёл initialize и сообщил Element 9.2.4.
- MCP отклоняет LSP-запросы на изменение workspace и хранит metadata вне исходного проекта.

## [0.9.0] - 2026-07-21

- Добавлен кэшируемый индекс объявлений подключённого проекта с поддержкой русских и английских XBSL-ключевых слов, методов, структур, перечислений и исключений.
- `lookup_symbol` находит YAML-элементы и XBSL-объявления, сохраняет перегрузки и возвращает полный контекст элемента-владельца.
- `find_references` ищет точные границы идентификатора, исключает строки и комментарии и явно отделяет достоверные объявления от лексических ссылок средней уверенности.
- `get_related_docs` преобразует символ или файл проекта в обогащённый запрос к нормализованному корпусу и сохраняет версию и происхождение найденных документов.
- В MCP instructions закреплена граница: лексический индекс не подменяет компилятор или Language Server и не должен скрывать неоднозначность.
- Индекс проверен на полном исходном проекте Панели управления 9.2.4-6: 4 039 доступных исходных файлов и 18 451 объявление после исключения строк и комментариев.

## [0.8.0] - 2026-07-20

- Добавлен необязательный безопасный handoff контекста Element IDE в локальный MCP без передачи Client-Secret модели или инструментам Codex.
- Перед активацией MCP проверяет присланные IDE credentials реальным чтением пространств; отклонённый контекст не заменяет рабочее подключение.
- Контекст IDE имеет приоритет над статической конфигурацией, хранится только в памяти процесса и автоматически исчезает после перезапуска MCP.
- Обычный VS Code с официальным Codex продолжает работать независимо через `stdio`, переменные окружения или защищённый `console.json`.
- Добавлены локальный интеграционный endpoint, защита host/CSRF, лимит тела запроса и тесты отсутствия секретов в ответах и файлах.

## [0.7.0] - 2026-07-20

- Добавлен read-only клиент API Панели управления и инструменты проверки подключения, списка пространств, каталога проектов пространства и чтения одного проекта.
- MCP агрегирует идентификаторы из `/api/v2/spaces/{SpaceId}/projects` с полными метаданными `/api/v2/projects/{ProjectId}` и различает пустой список, `401`, `403`, `404` и сетевую недоступность.
- Поддержаны окружение, отдельный `console.json`, настройки Element/VS Code и provisioning context; выбранное пространство может определяться по `1C.projectId`.
- В режиме `stdio` MCP обнаруживает настройки только в известных файлах текущего workspace. Для HTTP-службы Windows путь к настройкам IDE задаётся установщику явно.
- Client-Secret и access token не являются аргументами MCP tools и не возвращаются агенту. Windows-конфигуратор хранит Client-Secret через DPAPI LocalMachine и ограничивает ACL файла.
- Добавлены повторное получение токена после `401`, проверка TLS по умолчанию и поддержка собственного CA bundle для закрытых контуров.

## [0.6.0] - 2026-07-20

- MCP распознаёт `Project.yaml`/`Проект.yaml`, подсистемы, YAML-виды элементов и связанные модули XBSL/XBQL.
- Добавлены обзор проекта, фильтруемый список элементов, ограниченный текстовый поиск и построчное чтение исходников.
- Все файловые операции ограничены подключённым корнем, разрешёнными текстовыми форматами и лимитами размера.
- В server instructions закреплён Element-aware процесс: сначала метаданные YAML, затем связанные модули и код.
- Имя MCP-сервера расширено с документационного на общее `1C Element`.

## [0.5.0] - 2026-07-20

## [0.4.0] - 2026-07-20

- Нажатие «Проверить обновления» сохраняет изменённый путь и автоматически устанавливает более новую локальную версию.
