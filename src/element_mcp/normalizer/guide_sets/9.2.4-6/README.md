# Нормализованный корпус документации «1С:Предприятие.Элемент»

Этот каталог — локальная база знаний для ИИ-агентов и разработчиков MCP/Skills. Корпус объединяет официальную документацию, исходники Management Console, конфигурацию серверного бандла, индексы кода и аналитические руководства.

## Состав

- `docs-lang` — язык XBSL/XBQL, модель разработки и стандартная библиотека.
- `docs-console` — вся Management Console: исходники, метаданные, HTTP API, подсистемы и сценарии работы.
- `docs-server` — серверный бандл, Java-модули, IDE, LSP, Executor, конфигурация и эксплуатация.
- `tools` — воспроизводимая сборка, валидация и гибридный поиск.
- `sources.yaml` — реестр исходных релизов. При выходе новой версии сюда добавляется новая запись.
- `reference-catalog.json` — проверяемый каталог точных версионных JSON/JSONL-справочников.

## Быстрый поиск

```bash
python3 codex-docs/tools/search.py "загрузить сборку проекта" --corpus console
python3 codex-docs/tools/search.py "объявление метода и аннотации" --corpus lang
python3 codex-docs/tools/search.py "запуск LSP через stdio" --corpus server
python3 codex-docs/tools/search.py "debug application" --corpus all
```

Поиск гибридный: SQLite FTS5/BM25 плюс плотный локальный вектор на основе feature hashing и символьных n-грамм. Он не требует внешнего API и остаётся воспроизводимым. Для смыслового reranking агент может передать найденные чанки своей embedding-модели.

## Пересборка и новая версия

```bash
python3 codex-docs/tools/build.py --all
python3 codex-docs/tools/validate.py
```

Порядок обновления описан в [VERSIONING.md](VERSIONING.md), формат документов и чанков — в [CORPUS_FORMAT.md](CORPUS_FORMAT.md).

## Правило использования агентом

1. Сначала читать `README.md` нужного корпуса и подходящее руководство в `guides/`.
2. Для точного API-контракта или инвентаря использовать `reference-catalog.json`; для объяснений искать по индексу.
3. Проверять `product_version`, `source_version`, `is_current` и `provenance` результата.
4. При изменении кода Console сверяться и с аналитическим руководством, и с исходным `.yaml`/`.xbsl`.
5. Не считать автоматически сгенерированное описание заменой исходного файла: каталоги и индексы предназначены для навигации, а источник остаётся окончательной проверкой.
