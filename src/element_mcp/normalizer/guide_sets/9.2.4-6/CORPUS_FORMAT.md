# Формат корпуса

## `documents.jsonl`

Одна строка — один нормализованный документ. Основные поля:

- `id`, `logical_id`, `corpus`, `kind`, `title`;
- `product_version`, `source_version`, `is_current`;
- `source_path`, `source_uri`, `normalized_path`, `provenance`;
- `tags`, `language`, `sha256`, `text`.

## `chunks.jsonl`

Одна строка — атомарный поисковый фрагмент. Чанк содержит `id`, `document_id`, `logical_id`, заголовок документа, секцию, позицию, версии, теги, provenance и сам текст. Чанки стараются не разрывать Markdown-секции и объявления методов.

## SQLite

`index.sqlite` содержит метаданные `documents`, полные `chunks`, виртуальную таблицу FTS5 `chunks_fts` и метаданные сборки. FTS использует external-content mode: текст хранится в `chunks` один раз, а виртуальная таблица содержит поисковый индекс. Токенизатор `unicode61` работает с русским и английским текстом и идентификаторами.

## Векторы

- `vectors.f16.npy` — L2-нормированные плотные векторы чанков;
- `vector-ids.jsonl` — соответствие строки матрицы чанку;
- `vector-idf.npy` — веса признаков для запроса;
- `vector-meta.json` — алгоритм, размерность и хеш входного набора.

Вектор строится из слов, частей CamelCase/snake_case, биграмм и символьных n-грамм. Такой индекс особенно полезен для API-маршрутов, XBSL-идентификаторов и близких написаний терминов.

## Provenance

Каждая запись должна позволять вернуться к первоисточнику. Значение `provenance` принимает одно из значений:

- `official-html` — официальная страница документации;
- `embedded-source` — исходник из поставки;
- `bundle-file` — файл бандла;
- `jar-inventory` — сведения, извлечённые из JAR;
- `derived-analysis` — аналитическое руководство, подготовленное по нескольким источникам.
