# Архитектура Management Console

## Что представляет собой Console

Management Console — не отдельный Java web frontend, а крупное прикладное приложение самой платформы «1С:Элемент». Java-модуль PaaS Manager загружает упакованную конфигурацию `e1c/console`; платформа исполняет её метаданные, XBSL, формы, хранилища и HTTP-сервисы. Поэтому граница проходит так:

```text
HTTP/IDE/UI
  → HttpService или InterfaceComponent (YAML)
  → handler/событие (XBSL)
  → API/service/manager-модуль
  → каталог, документ, регистр, task/workflow
  → Java-сервисы платформы, кластеры, СУБД и внешние системы
```

`Project.yaml` задаёт имя, версию и языки проекта. `Project.xbsl` импортирует крупные подсистемы и содержит установочные/миграционные обработчики. Корневые `Subsystem.yaml` описывают связи `Using`; XBSL `import` формирует фактический граф использования экспортируемых сущностей.

## Слои

### UI и навигация

`InterfaceComponent`, формы, command-interface fragments, navigation routers и client events образуют административный интерфейс. UI не должен напрямую выполнять инфраструктурные операции: он вызывает менеджеры и создаёт задания.

### Доменный слой

Каталоги, документы, структуры, перечисления и регистры хранят проекты, сборки, приложения, подписчиков, пользователей, экземпляры и историю операций. Модули `*.Object.xbsl` реализуют поведение экземпляра хранимой сущности; обычные `*.xbsl` — коллекцию/manager/global behavior.

### Оркестрация

Длительные и составные действия проходят через `TaskManagement`, специализированные producers/managers и workflow/step flow. Статус UI/API часто отражает агрегированное состояние задания, а не один синхронный вызов.

### API

`API`, `API_V2`, `PaasGateAPI` и специализированные HTTP-сервисы публикуют разные поверхности: внешний административный API, internal endpoints, self-service и интеграционные контракты. Контроллер выполняет access check, разбирает параметры/тело, вызывает service и сериализует DTO.

### Адаптеры инфраструктуры

`Instances`, `Ecrun`, `G5Platforms`, `Dbms`, `ObjectStorages`, `ReverseProxy`, `DomainNames`, `Monitoring` и `Logging` переводят доменные операции Console в действия над сервером и внешней инфраструктурой.

## Инициализация и обновление

`@ApplicationSetup` выполняет начальную настройку: пересчёт прав, legacy updates, обработчики внешних monitoring states, exporters, шаблоны услуг и scheduling приложений. Последовательность `@ProjectUpdate(Order=...)` обновляет доступ, данные сборок, context paths, jobs, репозитории, проектные группы и новые подсистемы. Изменение Console должно сопровождаться новой миграцией, если существующие данные не соответствуют новой модели.
