# Рабочий процесс ИИ-агента при разработке на «1С:Элемент»

## Перед изменением

1. Определить версию проекта и платформы.
2. Найти `Project.yaml`, `Project.xbsl` и `Subsystem.yaml` целевой области.
3. Найти одноимённые YAML/XBSL-файлы изменяемого элемента.
4. Поискать символ и тип по корпусу, затем по LSP workspace symbols/references.
5. Изучить соседние реализации того же `ElementKind`.

Корпус отвечает на вопрос «как это задумано и какие есть примеры», LSP — «валидно ли это в конкретном проекте», сборка — «может ли платформа собрать и применить проект».

## При генерации XBSL

- Сохранять язык ключевых слов и стиль существующего файла.
- Указывать типы там, где они проясняют контракт или требуются LSP.
- Не выдумывать типы и методы стандартной библиотеки: находить точную сигнатуру.
- Учитывать область видимости экспортируемых методов.
- Не расширять `AccessContext.Privileged()` за минимальную операцию.
- Для фоновых операций использовать существующий механизм заданий, статусов и результатов.
- Для внешнего API возвращать DTO, а не внутренние ссылки и объекты хранения.

## При генерации YAML

- Копировать структуру только с элемента того же вида и версии.
- Генерировать новый `Id`, не дублировать UUID примера.
- Проверять связь `Handler` с реально существующим методом XBSL.
- Для HTTP-сервиса проверять уникальность `RootUrl` и шаблонов.
- Явно проверять `AccessControl`; отсутствие ожидаемого ограничения — дефект безопасности.
- Не сортировать механически YAML, если порядок используется редактором или облегчает diff.

## Цикл проверки

Минимальный цикл для изменения:

1. синтаксическая диагностика YAML/XBSL;
2. LSP diagnostics по изменённым файлам;
3. поиск unresolved imports/references;
4. проверка сигнатур обработчиков;
5. сборка проекта;
6. при изменении метаданных — тест обновления существующей базы;
7. при изменении API — тест аутентификации, положительного и отрицательного сценария;
8. при изменении фоновой операции — тест повторного запуска, блокировок и ошибки посередине workflow.

## Как собирать контекст

Для одного изменения обычно достаточно 5–12 чанков:

- концептуальная страница `topics`;
- 1–3 страницы `stdlib` по типам и методам;
- YAML целевого элемента;
- связанный XBSL;
- один близкий пример;
- при необходимости — описание Console API или серверного модуля.

Не следует загружать целиком весь корпус в prompt. Используйте `tools/search.py`, затем расширяйте контекст по `source_path`, импортам и соседним файлам.
