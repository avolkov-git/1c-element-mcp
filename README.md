# 1c-element-mcp

MCP-сервер для работы ИИ-агентов с «1С:Предприятие.Элемент». Сервер умеет локально создавать нормализованный корпус из установленного серверного бандла, проверять и подключать его, а затем выполнять гибридный поиск по языку, Management Console и серверной платформе.

Текущая версия: **0.7.0**.

## Что делает сервер

- запускается даже без готовой документации;
- ищет установки Element в стандартных каталогах Windows и Linux;
- нормализует язык, всю Management Console и серверный бандл;
- создаёт Markdown, JSONL, SQLite FTS5 и локальные векторные индексы;
- включает наши аналитические руководства с provenance `derived-analysis`;
- проверяет целостность и подключает результат только после успешной сборки;
- не отправляет документацию или содержимое бандла во внешние сервисы.

Нормализатор `1.0.0` содержит проверенный комплект правил и руководств для Element `9.2.4-6`. Поддержка следующей версии добавляется новой версией нормализатора и новым эталонным набором.

## Встроенный сценарий нормализации

Начиная с версии `0.5.0`, полный безопасный сценарий подготовки документации передаётся агенту самим MCP
при подключении. Агент знает, что сначала нужно проверить состояние корпуса, не запускать тяжёлую сборку без
явного согласия, найти или запросить серверный бандл, дождаться завершения фоновой задачи и сообщить результат
валидации. Для поиска он получает правило сначала вызывать `search_docs`, затем читать выбранный фрагмент через
`get_document`.

Поэтому отдельный Skill не обязателен: достаточно подключить MCP. Skill `setup-element-documentation` можно
использовать дополнительно в клиентах, которые поддерживают Skills, — он делает тот же пользовательский сценарий
явным и переносимым, но сервер от него не зависит.

## Доступ к исходному проекту

Версия `0.6.0` добавляет безопасный контур чтения проекта. Сначала агент вызывает `get_project_status`. Если
проект ещё не подключён, он просит пользователя указать корень, проверяет наличие `Project.yaml` или
`Проект.yaml` и сохраняет выбор через `connect_project`. После этого конфигурация Codex не меняется.

MCP понимает структуру Element: выделяет проект и подсистемы, читает верхнеуровневые свойства YAML, группирует
элемент с одноимёнными модулями XBSL/XBQL и показывает окружение и область видимости. Поиск и чтение разрешены
только для `.yaml`, `.yml`, `.xbsl` и `.xbql` внутри подключённого корня. Абсолютные пути, выход через `..`,
символические ссылки наружу, бинарные `.xprj` и файлы крупнее 2 МБ не читаются. MCP не изменяет исходники.

Путь также можно зафиксировать при запуске:

```bash
element-mcp --transport stdio --project-path /absolute/path/to/element-project
```

или переменной `ELEMENT_PROJECT_PATH`. Такой путь имеет приоритет над сохранённой настройкой и меняется только
после перезапуска MCP.

## Проекты Панели управления

Версия `0.7.0` добавляет отдельный read-only контур Console:

- `get_console_status` проверяет настройки, получение токена и доступ к пространствам;
- `list_console_spaces` показывает пространства, доступные настроенной учётной записи;
- `list_space_projects` получает проекты пространства и дополняет их именами, описаниями, типами и состоянием;
- `get_console_project` читает один проект или текущий `1C.projectId` из окружения IDE.

Console возвращает для пространства только идентификаторы проектов, поэтому MCP сам получает полные сведения о
каждом проекте. Результат отражает права настроенной учётной записи: `403` не выдаётся за пустой список. Каталог
Console не предоставляет доступ к локальным исходникам. Для анализа кода выбранный проект по-прежнему нужно
связать с подтверждённым пользователем Git-каталогом через `connect_project`.

### Element IDE и VS Code

Плагин Element `9.2` использует настройки `1C.server`, `1C.clientId`, `1C.clientSecret` и `1C.projectId`. Когда
Codex запускает MCP как дочерний `stdio`-процесс, сервер проверяет известные файлы текущего workspace:
`.vscode/settings.json`, `.theia/settings.json`, `.settings/settings.json` и корневой `*.code-workspace`. Можно
явно передать объединённый файл настроек, который видит плагин:

```bash
element-mcp --transport stdio --ide-settings-path /absolute/path/to/settings.json
```

Поддерживается и provisioning context Element с вложенным объектом `settings` и ключами `paas-url`, `client-id`,
`client-secret`, `paas-project-id`, `paas-space-id`. Если задан `1C.projectId`, `list_space_projects` сначала
получает текущий проект и автоматически определяет его пространство.

Сам факт открытой браузерной сессии не передаёт cookie или внутренний кэш токена внешнему MCP. Прозрачный режим
работает, только когда плагин намеренно запускает MCP с нужными переменными окружения или предоставляет явно
выбранный файл настроек. Секреты не передаются через аргументы MCP tools и не появляются в диалоге.

### Отдельный MCP и Windows-служба

Для постоянно работающего HTTP-сервера используются переменные окружения или отдельный `console.json` рядом с
основным `config.json`. На стандартной Windows-установке это
`C:\ProgramData\1c-element-mcp\config\console.json`. Настройте его из PowerShell администратора: скрипт запросит
Client-Secret скрыто, зашифрует его Windows DPAPI и ограничит ACL файла системной учётной записью и
администраторами.

```powershell
.\scripts\configure-console-windows.ps1 `
  -Server "https://element-server/console" `
  -ClientId "<client-id>" `
  -ProjectId "<необязательный-project-uuid>"

Restart-ScheduledTask -TaskName "1C Element MCP"
```

Если служба должна читать уже существующий файл настроек Element/VS Code, передайте его установщику и повторно
запустите установку:

```powershell
.\scripts\install-windows.ps1 -IdeSettingsPath "D:\Element\settings.json"
```

Служба работает от `SYSTEM`, поэтому файл должен быть доступен этой учётной записи. Это подходит и закрытому
контуру: адрес Console может быть внутренним, а доверенный корневой сертификат задаётся полем `ca_bundle` или
переменной `ELEMENT_CONSOLE_CA_BUNDLE`. Проверка TLS включена по умолчанию.

Для контейнера, Linux или запуска из плагина доступны переменные:

```text
ELEMENT_CONSOLE_URL
ELEMENT_CONSOLE_CLIENT_ID
ELEMENT_CONSOLE_CLIENT_SECRET
ELEMENT_CONSOLE_ACCESS_TOKEN
ELEMENT_CONSOLE_PROJECT_ID
ELEMENT_CONSOLE_SPACE_ID
ELEMENT_CONSOLE_CA_BUNDLE
ELEMENT_IDE_SETTINGS_PATH
ELEMENT_CONSOLE_CONFIG_PATH
```

Access token имеет приоритет над парой Client-Id/Client-Secret и хранится только в памяти процесса. При
client credentials MCP получает `id_token` через `/sys/token`, кэширует его в памяти и один раз обновляет после
`401`.

## Подключение к Codex

MCP больше не требует указывать путь к корпусу при первом запуске:

```toml
[mcp_servers.element]
command = "/absolute/path/1c-element-mcp/.venv/bin/element-mcp"
args = ["--transport", "stdio"]
```

После успешной нормализации активный путь сохраняется во внутренней конфигурации MCP. Конфигурация Codex остаётся неизменной.

## Установка на Windows Server

Запустите PowerShell от имени администратора. Для приватного репозитория предварительно выполните `gh auth login` или задайте `GH_TOKEN`, затем:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\install-windows.ps1
```

Скрипт можно запускать повторно для обновления. По умолчанию он устанавливает MCP в `C:\ProgramData\1c-element-mcp`, регистрирует задание `1C Element MCP` от `SYSTEM` и запускает endpoint `http://127.0.0.1:9900/mcp`. Windows Firewall не открывается.

После установки откройте `http://127.0.0.1:9900/` в браузере на сервере. Страница показывает, что MCP запущен, установленную версию и наличие обновления. Кнопка обновления запускает отдельное задание `1C Element MCP Updater`: оно останавливает сервер, выполняет fast-forward и установку, затем снова запускает MCP. При ошибке код и Python-пакет возвращаются к предыдущей версии.

### Откуда брать обновления

По умолчанию проверяется ветка `master` удалённого `origin`. Это простой вариант для сервера с доступом к GitHub и учётными данными Git, доступными системной учётной записи `SYSTEM`. Для приватного репозитория обычно удобнее локальный источник: авторизация администратора, выполнившего установку, автоматически не передаётся фоновому заданию.

Для закрытого контура подготовьте доступный серверу локальный клон или Git-зеркало. Путь можно передать при установке:

```powershell
.\scripts\install-windows.ps1 -UpdateSourcePath "D:\MCP-Mirror\1c-element-mcp"
```

Или открыть в UI «Изменить» рядом с источником обновлений и указать полный путь, например `C:\Users\cibot\Desktop\1c-element-mcp`. После изменения основная кнопка называется «Сохранить и проверить»: MCP проверяет, что каталог является доверенным Git-клоном проекта и содержит ветку `master`, сохраняет выбор в `config.json` и сравнивает версии. Если локальная версия новее, Windows-установщик сразу ставит её и перезапускает MCP — отдельное подтверждение не требуется.

В этом режиме все последующие проверки и обновления читают выбранный локальный Git-каталог. Сам клон можно обновлять через `git pull`, внутренний Git-сервер или переносом в закрытый контур. Кнопка «Переключиться на удалённый origin» сохраняет обычный сетевой режим немедленно и подтверждает изменение на странице. MCP не выходит в интернет, пока выбран локальный источник. Если источник временно недоступен, сервер продолжает работать, а UI предлагает повторить проверку.

Изменение источника защищено локальным токеном страницы и доступно только через loopback-интерфейс. Задание обновления работает от `SYSTEM`, поэтому эта учётная запись должна иметь право чтения выбранного каталога. Выбор каталога означает доверие к находящемуся в нём коду: обновлятор принимает только проект `1c-element-mcp` и только fast-forward относительно установленной версии.

Файл установщика намеренно содержит только ASCII-символы: это обеспечивает одинаковый разбор в Windows PowerShell 5.1 на системах с любой активной кодовой страницей.

Для временного или заранее подготовленного корпуса путь можно передать явно:

```bash
element-mcp --transport stdio --corpus-path /absolute/path/to/codex-docs
```

## Локальные каталоги

Пути выбираются по правилам операционной системы:

- Windows: `%LOCALAPPDATA%\1c-element-mcp`;
- Linux: `~/.local/share/1c-element-mcp` и `~/.config/1c-element-mcp`;
- macOS: `~/Library/Application Support/1c-element-mcp`.

Их можно переопределить параметрами `--data-path`, `--config-path` или переменными `ELEMENT_MCP_DATA_PATH`, `ELEMENT_MCP_CONFIG_PATH`. Явный `--corpus-path` и `ELEMENT_DOCS_PATH` имеют приоритет над сохранённым активным корпусом.

## Как проходит сборка

Нормализатор проверяет наличие `docs/help/ru`, JAR Management Console, `ide` и `executor`. Результат сначала создаётся в изолированном каталоге `.building-<job-id>`. Затем проверяются JSONL, SHA-256, SQLite, FTS и размеры векторных матриц. Только прошедший проверку каталог атомарно переименовывается и становится активным.

Для Element `9.2.4-6` дополнительно проверяются эталонные показатели:

- 9 925 документов;
- 59 522 чанка;
- точные хеши документов и входов векторных индексов для всех трёх корпусов.

Сборка занимает несколько минут и создаёт около 620 МБ данных. При ошибке старый активный корпус не меняется.

## Streamable HTTP

```bash
element-mcp --transport streamable-http --host 127.0.0.1
```

Порт по умолчанию — `9900`. Endpoint: `http://127.0.0.1:9900/mcp`.

Локальный UI: `http://127.0.0.1:9900/`.

До появления встроенной аутентификации публичная HTTP-привязка запрещена. Для удалённого размещения требуется закрытый reverse proxy или иной аутентифицирующий слой.
